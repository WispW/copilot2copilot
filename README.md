# Copilot2Copilot

在 GitHub Copilot 中注册“向同事沟通”工具，让**双方的 Copilot 直接沟通**：你告诉自己的 Copilot “帮我问张三：XX 接口的分页参数怎么传”，消息会送达同事的 VS Code，由其 Copilot 阅读理解并回复；代码细节的往返全程自动流转。

## 功能

- **10 个语言模型工具**（agent 模式下 Copilot 自动调用，也可用 `#` 引用）：
  - `#c2c_list_colleagues` 查看**在线** Copilot 列表（含角色、负责内容；传 `include_offline=true` 可查看全部已配置条目）
  - `#c2c_send_message` 向同事发消息（可附代码片段；`intent=task` 表示请对方执行写操作；**默认等待对方回复后再返回结果**）
  - `#c2c_wait_reply` 等待某条消息的回复
  - `#c2c_reply_message` 回复收到的消息
  - `#c2c_list_inbox` 查看收件箱（同事发来的消息 + 已收到的回复；含文件信息与落盘路径）
  - `#c2c_send_file` 给同事发送文件（扩展负责分块传输、逐块确认与 sha256 校验；双方需同时在线，单个文件上限 64 MiB）
  - `#c2c_query_memory` 查询房间共享记忆（提问前先查，避免重复问答；返回条目带出处与修订号）
  - `#c2c_remember` 把可复用的事实写入房间共享记忆（房间成员共享、全员可改）
  - `#c2c_update_memory` 修正共享记忆条目（携带 revision，冲突会回传最新内容）
  - `#c2c_forget_memory` 删除共享记忆中过时 / 错误 / 重复的条目（软删除，可在「记忆」页回收站恢复）
- **中继模式**：双方各自连接自建中继服务器；消息由中继转发、离线消息由中继暂存、在线档案（角色 / 负责内容）由中继集中下发
- **房间（可见域）**：房间由**中继管理员**统一创建与管理（建房、改名、改/清密码、归类、移出成员（移出即禁止再加入，可解除）、解散；分类仅用于分组与排序）；**房间列表（名称 / 分类 / 人数 / 是否有密码）对所有设备可见，凭密码加入**，成员明细仅成员与管理员可见。设备只能看到、并只能与**同房间成员**通信——非同房间的消息会被中继拒转并向发送方回执。房间、分类、成员与禁止名单**落盘保存**（`rooms.json`），中继重启后保留。**未加入任何房间时看不到任何人**，需先凭密码加入由管理员创建的房间
- **房间共享记忆**：每个房间一份由中继托管的共享记忆（成员全员可读可改）：Copilot 提问前先检索、拿到结论后写入，避免重复问答；条目带修订号（乐观锁，不静默覆盖）、保留历史版本、支持软删除与回收站恢复；需要连接中继才能使用
- **中继管理权限（admin）**：在配置界面填入中继的**管理令牌**后，可查看在线设备（含各自扩展版本）、踢出、封禁/解封，并管理所有房间与分类；管理操作只在界面手工执行，不暴露给模型工具
- **版本门禁**：连接时上报扩展版本，中继只放行与自己**版本一致**的扩展（`-testN` / `-testN.M` 测试包后缀忽略），不一致会拒绝接入（4008）并给出提示——中继与扩展需同步升级
- **连接由你掌控（不做自动重连）**：连接只在两种时机发起——VS Code 启动时自动一次（可在「连接」页关掉），以及你点「连接 / 重试连接」时。任何中断（中继未运行、地址或令牌错误、被踢出、被封禁、网络抖动）都会停在失败态并给出原因与下一步动作，**不会在后台反复向中继发起请求**。界面顶部常驻「连接 / 断开连接」按钮（命令面板另有 `Talk2Copilot: 断开连接`），断开后再点「连接」即可恢复，未发出的消息会在连上后补发
- **左下角状态栏入口**：状态灯 + 未读角标，点击打开配置界面（连接 / Copilot 列表 / 房间 / 管理 / 收件箱 / 行为 / 帮助）
- **下线通告**：VS Code 退出时向所有沟通方发出下线通告，对端立即把它从 Copilot 列表移除（离线条目不再显示在列表里）
- **档案自动交换**：连上中继后自动同步双方的角色 / 负责内容，供双方 Copilot 判断“该问谁”“谁在问”；档案可**按工作区**配置，切换项目时自动生效
- **防注入设计**：通信约定与安全边界保存在扩展内 `prompts/communication-boundary.md`，注入时作为**附件**加载（不占用消息正文）；所有发送动作都有确认弹窗

## 开发与安装

```bash
npm install
npm run build        # 产出 dist/extension.js（扩展宿主）与 dist/webview.js（配置界面，Preact + TSX）
npm run typecheck    # 类型检查
npm run vsix         # 打包 vsix 到 vsix/ 目录（文件名含版本号），发给同事安装
```

## 配置

点击左下角状态栏的 `talk2copilot` 图标打开配置界面：

- **连接**：顶部常驻状态灯与「连接 / 断开连接」按钮。填中继服务器地址（`wss://` 或 `ws://`）与自己的档案 id；中继令牌与**中继管理令牌**均可选（都存系统密钥库）。管理令牌填对后即获得中继管理权限；「连接」页还会显示中继运行版本与本机扩展版本供对照，并可关闭「启动 VS Code 时自动连接一次」。界面上的「保存并应用」只在有改动时可点（改了字段才会亮），「重新载入」放弃未保存的修改
- **断开连接**：点顶部「断开连接」（或命令面板 `Talk2Copilot: 断开连接`）即停止通道，不会自动重连；工具调用会提示「通道未连接」，点「连接」恢复
- **本工作区档案**：id、角色、负责内容（必填齐全才能通信，未完善时状态栏与配置页会提示）。档案**按工作区保存**，本机每个窗口各持一份 —— 因此多个窗口可以各有各的 id，不会在中继上互相顶下线。首次在某个工作区启用时会自动生成一个唯一 id（可在界面修改），并把「模板」里的角色与负责内容预填进来
- **模板**：「维护 → 把当前角色/负责内容存为模板」，用于给以后新开的工作区预填角色与负责内容。模板**不含 id**，避免新窗口与现有窗口撞名
- **Copilot 列表（由中继自动维护）**：中继下发**在线名单与在线档案**（角色/负责内容），扩展据此自动登记与更新列表，**无需手工添加或编辑**；列表只显示**在线**的 Copilot（对方下线后条目立即消失），`#c2c_list_colleagues` 同样默认只返回在线条目（传 `include_offline=true` 可看全部已配置条目）。同一台机器的多个窗口共用一份全局配置，别的窗口在列表里看到本窗口时会把它登记成条目——这类**指向自己的条目会被隐藏**，既不能发送也不会进入模型可见列表；档案同步完成前无法收发消息
- **停用沟通方**：条目右侧是**单个「停用/启用」按钮**，点一下立即切换（停用后按钮文字变为「启用」，卡片置灰并显示「已停用」）。条目**不能删除**（只由中继目录维护），只能**停用**。停用后：不出现在模型可见的 `#c2c_list_colleagues` 列表里；向它发送或回复会被拒绝；它发来的消息与回复也不再自动触发本机 Copilot 对话（仍会记入收件箱，便于查看）。注意两点边界：停用**不会**主动断开已建立的中继连接，也**不会**撤回停用前已排队待发的消息
- **可执行（写权限）**：卡片右上角「停用」旁的「可执行」开关——逐同事授权该同事派发**写任务**；默认关，撤销后完全回到只读。详见下文「可执行授权与无人值守（v2）」
- **行为**：等待回复默认超时、历史消息保留条数、写任务系统通知（可静音）；收到同事的消息或回复时是否**自动触发本机 Copilot 对话**由顶部「无人值守」开关决定（默认关，只进收件箱）
- **房间**：查看中继上的房间列表（名称、分类、人数、是否需要密码对所有人可见；成员明细仅成员与管理员可见），凭密码加入 / 退出。房间与分类由**中继管理员**统一管理：创建房间（可设加入密码、选分类）、改名、改/清密码、归类、移出成员、解除禁止再加入、解散；**房间与分类落盘（`rooms.json`），重启保留**。分类只用于分组与排序，不影响权限
- **管理**：填入中继管理令牌后，可查看在线设备（id / 扩展版本 / 所在房间数）并执行**踢出**与**封禁**（封禁后对方无法接入本中继）；下方封禁名单可**解除封禁**。该设备列表**不受房间限制**（管理需要），但你的通信与 Copilot 列表仍受房间约束。注意：被踢出或被封禁的设备**不会自动重连**（本扩展不做自动重连），解封后需对方手动点「重试连接」

### 列表与实时刷新

- **中继模式**：连上中继后先向中继**上报自己的档案**（信包以 `to='server'` 发出，不进离线暂存）；服务端维护在线档案目录，并在成员上下线、档案更新时把在线名单（`peers`）与在线档案（`profiles`）广播给所有在线设备；扩展据此自动登记/更新 Copilot 列表（跳过自己）。**档案由中继统一下发**，客户端不再互发档案声明（对端随消息携带的 profile 仅作补充）。需中继服务端同步升级：未升级的中继只广播在线 id，拿不到对方的角色/负责内容（显示为「档案未同步」，此时无法收发消息）
- 中继会收录**任何持有令牌的在线设备**，列表可能被陌生 id 撑大——用「停用」处理即可
- 配置界面为**实时刷新**：任何状态变化（上下线、档案更新、收发消息）都会立即推送到界面；界面用 Preact 局部更新，不会打断你正在输入的草稿内容

### 可执行授权与无人值守（v2）

v2 在**只读问答**之外开放了**受限的写任务**，授权源头始终是本机用户本人：

- **写权限（逐同事、默认关）**：「Copilot 列表」卡片右上角的「可执行」开关。打开后该同事可用 `intent=task` 请求本机 Copilot 执行写操作；撤销后立刻回到只读。顶部状态行显示「可执行授权 · N 位」（点它到列表逐人管理），「行为 → 维护」提供「**取消所有写授权**」一键全关
- **红线**：删除、安装依赖、有副作用的命令（部署 / 重启）、工作区外路径——即使授权也一律拒绝，并由对方 Copilot 回执说明
- **无人值守（默认关）**：顶部状态行的开关。**关闭**时同事发来的消息与文件只进收件箱并计入「N 条未回复」（**不自动唤醒**本机 Copilot），同时给对方一条「已送达，待人工处理」的自动回执；**打开**后按上面的授权规则自动注入当前对话处理
- **手动处理**：收件箱每条待处理记录带「**交给 Copilot**」按钮，把它注入当前对话（无人值守关闭时的主要入口）
- **系统通知（默认开）**：写任务开始 / 结束时用系统通知提醒本机用户（Linux `notify-send`、macOS `osascript`；不可用时退回 VS Code 内通知），可在「行为」页静音
- **收件箱会话化**：按同事分会话（微信式）——会话列表显示最后一条摘要与待处理条数，点进会话看气泡详情；写任务用特殊卡片标识
- **身份按工作区**：换工作区 = 换 id。旧身份上开过的「可执行」不会继承到新身份（新身份默认全关），对方列表里会多出一个属于该工作区的条目；给谁发消息时注意选对 id
- **取消排队**：对方离线或通道断开时，消息会留在本机待发队列里、连上后自动补发；这条记录在「收件箱」里带 **「取消排队」** 按钮（两步确认），取消后对方上线也不会再补发
- **沟通纪律（替代原熔断）**：不再有基于往来条数的自动中止，改为在提示词与边界文档里约束——先发现、汇总、检查无遗漏后再发送，信息足够即停止；「等待超时先看对方是否在线」保持不变

`id` 是双方匹配的唯一依据，两端需互不相同；连上同一中继的设备会自动互相登记到列表中（指向自己的条目会被隐藏，也无法给自己发送）。

### 多窗口（同一台机器开多个 VS Code）

档案按工作区保存，因此**同一台机器的每个窗口都可以有各自的 id 并同时在线**。为避免两个窗口用同一个 id 互相顶下线，扩展做了三重处理：

1. **首次启用自动生成唯一 id**：在某个工作区第一次启用时，id 自动生成为 `<模板 id>-<4 位随机>`（例如 `qq341-3f2a`），并保存在该工作区里，重载窗口不变
2. **连接前预检**：中继模式下连接前会带令牌查询中继的在线名单（`GET /peers`），若自己的 id 已在线会给出提示（可能是断电后残留的死连接），但仍会尝试连接，由服务端裁决
3. **服务端权威拒绝 / 接管**：中继对**仍活着**的同 id 连接回 `4005` 拒绝（不顶掉对方窗口）；对已失去心跳的死连接（断电/断网残留、TCP 半开）直接**接管**，让设备重启后能马上重连。客户端**不做自动重连**：收到 `4001/4002/4004/4005` 这类关闭码时，界面会写明原因（如「该中继 id 已被另一个窗口占用」）并停下，等你在顶部点「重试连接」——旧窗口确实已关闭时，重试即可接管死连接

## 使用示例

A（你）在 Copilot Chat（agent 模式）中说：

> 帮我问张三，OrderService 的 pageSize 上限是多少，把这段调用带给他

你的 Copilot 会调用 `#c2c_send_message`（弹出确认框，可核对内容与代码片段），消息送达后**在对方开启「无人值守」时直接触发对方的 Copilot 对话**进行处理（未开启则只进对方收件箱并回一条自动回执），回答经 `#c2c_reply_message` 返回。**发送默认等待对方回复**（缺省取配置里的“等待回复默认超时”，默认 90 秒）——拿到回复后本机 Copilot 才继续下一步；若等待超时，工具会提示暂停其他步骤、继续调用 `#c2c_wait_reply` 直到拿到回复（避免"边干活边等"导致回复无人认领、只能作为排队消息注入对话）。显式传 `wait_seconds=0` 可改为不等待。

需要让对方**改东西**时，用 `#c2c_send_message` 并带 `intent=task`（或直接说清要改什么、验收标准）。能否执行取决于**对方用户**是否在该同事卡片上打开了「可执行」：未授权时对方会回复「本机未开启执行授权」，此时把情况交给本机用户即可，不要反复重发。

### 交接文件（send_file）

需要把一份**文件**（源码、配置、日志、图片等）交给同事时，让 Copilot 调用 `#c2c_send_file`（确认弹窗中会展示文件名、大小与源路径）：

- **传输由扩展完成**：512 KiB 分块、逐块确认、整体 sha256 校验，返回 `status=ok` 表示对方已收妥落盘；全程不经过双方模型，文件内容不会进入对话
- **前提**：双方同时在线（离线不会排队补发）；单个文件上限 **64 MiB**；一次一个文件（多个文件就多次调用）
- **接收端**：文件落到扩展私有收件目录 `globalStorage/WispW.copilot2copilot/files/`（**不会写入工作区**），注入消息里给出完整路径，收件箱条目也会显示。重名文件自动加序号，绝不覆盖已有文件；中断/校验失败的分片会被丢弃
- **边界**：对方只能**只读**查看收到的文件；是否把它应用（复制/覆盖）到对方工作区，由**对方用户**决定，仍按正常流程走
- 「收件箱」页的「打开收件目录」按钮可在文件管理器中直接打开该目录
- 若在附言里向对方提了问题，对方回复后可用 `#c2c_wait_reply`（`request_id` 即 `send_file` 返回的编号）继续等待

## 中继服务器部署

中继服务跑在一台**独立服务器**上，双方各自连它、使用**同一个预共享密码**通信。目标机需有 Node.js 18+。

```bash
# 方式一：一键下载并部署（在目标服务器上执行，装到 /opt/talk2copilot-relay 并注册 systemd 服务）
d=$(mktemp -d) && curl -fsSL https://github.com/WispW/copilot2copilot/archive/refs/heads/master.tar.gz \
  | tar -xz -C "$d" && sudo "$d/copilot2copilot-master/relay/deploy/install.sh"

# 需要指定 node 时（nvm 装的 node 在 sudo 下不在 PATH，脚本会把它复制进安装目录，
# 因为 systemd 单元的 ProtectHome 会隐藏 /home）：
d=$(mktemp -d) && curl -fsSL https://github.com/WispW/copilot2copilot/archive/refs/heads/master.tar.gz \
  | tar -xz -C "$d" && sudo "$d/copilot2copilot-master/relay/deploy/install.sh" /home/<用户>/.nvm/versions/node/v22.11.0/bin/node

# 方式二：已把仓库放到目标机时，直接在仓库里执行
sudo relay/deploy/install.sh
sudo relay/deploy/install.sh /usr/local/bin/node   # node 不在 PATH 时指定绝对路径

# 方式三：前台直接跑（用于临时调试）
TALK2COPILOT_TOKEN=<你的密码> node relay/server.js 8787
```

把 `master` 换成 tag（如 `v0.3.9`）即可固定版本。若目标服务器访问 GitHub 不通，先在能联网的机器上下载该归档再拷过去，按方式二执行。

安装脚本会：**首次安装**时生成随机预共享密码**与管理令牌**写入 `/etc/talk2copilot-relay.env`（权限 600，含 `PORT` / `HOST` / `TALK2COPILOT_TOKEN` / `TALK2COPILOT_ADMIN_TOKEN` / `LOG_LEVEL`，模板见 `relay/deploy/relay.env.example`；已存在则原样保留），创建无登录权限的服务账号 `talk2copilot`，安装并启用 `talk2copilot-relay.service`，最后自查一次 `/healthz`（并比对运行版本与仓库 `package.json` 是否一致）。改完配置执行 `sudo systemctl restart talk2copilot-relay`。

运维命令：

```bash
sudo systemctl status talk2copilot-relay    # 运行状态
curl -s http://127.0.0.1:8787/healthz       # 探针：{"status":"ok","version":"0.4.1","protocol":2,"peers":..,"rooms":..,"bans":..,"queued":..,"tokenRequired":true,"adminEnabled":true}
curl -s -H "Authorization: Bearer <密码>" http://127.0.0.1:8787/peers   # 在线 id 列表（客户端连接前会自查此接口）
sudo journalctl -u talk2copilot-relay -f    # 日志（带时间戳与级别，可用 LOG_LEVEL 调级别）
```

- `HOST` 默认 `0.0.0.0`，内网各机可直连；只允许反向代理 / 隧道访问时改为 `127.0.0.1`
- **版本门禁（0.4.1 起）**：中继只放行扩展版本与自己一致的客户端。中继版本取 `relay/server.js` 顶部的 `RELAY_VERSION`（须与仓库 `package.json` 的 `version` 同步；`install.sh` 部署后会比对 `/healthz` 并告警）。**升级中继后必须同步升级所有客户端的扩展**，否则会被拒绝接入（4008，界面会提示双方版本）
- **管理令牌（0.4.1 起）**：`TALK2COPILOT_ADMIN_TOKEN`，留空则管理功能整体关闭。在扩展「连接」页填入同一字符串即获得管理权限（查看/踢出/封禁在线设备、管理所有房间）；令牌错误不影响普通连接，只是没有管理权限。**就地升级旧版本时安装脚本会自动补一行**（想指定值就先 `TALK2COPILOT_ADMIN_TOKEN=... sudo -E ./install.sh`），部署后可用 `curl /healthz` 看 `adminEnabled` 是否为 true
- **房间与封禁名单都落盘**在 systemd `StateDirectory`（默认 `/var/lib/talk2copilot-relay/`，单元已声明 `StateDirectory=talk2copilot-relay`）：封禁名单 `bans.json`、房间与分类状态 `rooms.json`，重启保留；备份 / 迁移时拷贝这两个文件即可
- **房间可见性（0.4.1 起）**：设备只能看到并只能与同房间成员通信；**未加入任何房间的设备与所有人互相不可见**。房间列表全员可见但加入需要密码，因此升级/部署后请**由管理员创建房间并把密码发给同事**，对方凭密码加入后双方的 Copilot 列表才会出现成员
- 收到 `SIGTERM`（`systemctl stop` / `restart`）时先给客户端发关闭帧再退出；客户端**不会自动重连**，界面会提示「无法连接中继服务器」，待中继起来后点「重试连接」即可
- 在线名单、**在线档案目录**与离线暂存都在内存中，**重启服务端会丢弃暂存的离线消息**；在线设备重连后会自动重新上报档案
- **在线档案目录（0.4.0 起）**：客户端连上后向中继上报自己的角色/负责内容，中继登记后在成员上下线、档案变更时广播给所有在线设备（`presence` 的 `profiles` 字段）。未升级的中继只广播在线 id（`peers`），此时客户端拿不到对方的角色/负责内容（显示「档案未同步」，无法收发消息）——请同步升级中继

跨网络使用时可置于 Cloudflare Tunnel / Nginx 之后（需支持 WebSocket），地址形如 `wss://relay.example.com`，客户端会自动拼 `/ws`。

## 安全说明

- 建议走 `wss://`，可设置中继令牌（校验 `Authorization: Bearer`，令牌存系统密钥库）
- **管理令牌（`TALK2COPILOT_ADMIN_TOKEN`）等同中继管理员**：持有者可踢出/封禁任意设备、管理所有房间。请只在自己的客户端填写，不要在共享机器上保存；中继未配置该变量时管理功能整体关闭
- **房间是可见域而非加密**：中继负责校验与转发，因此中继本身可见明文消息（与点对点时代的信任模型一致）；加入密码用于准入控制（scrypt 加盐哈希存储），不是端到端加密
- **通信边界**：默认仍是只读通道——**允许**对方回答信息、阅读代码、执行只读查询（获取信息）；**禁止**要求或执行任何变更（修改代码/文件/配置、安装依赖、部署、重启、启停服务等）。约定保存在扩展内 `prompts/communication-boundary.md`，注入同事消息/回复时作为附件加载
- **写任务（v2）**：只有在本机用户于「Copilot 列表」给该同事打开「可执行」后，对方带 `intent=task` 的任务才会按读写版约定（`prompts/communication-boundary-write.md`）执行，且限定在当前工作区内；删除、装依赖、有副作用的命令、工作区外路径等红线一律拒绝。授权逐同事、默认关、可随时撤销，任务内容始终是外部输入，本地规则（如仓库 `AGENTS.md`）优先
- 收到消息注入聊天时会声明为外部输入；「无人值守」开启时请谨慎对待不可信来源的消息（尤其是写任务）
- **同事发来的文件不可信**：文件由扩展落盘到私有收件目录（不进入工作区），只能只读查看；写入工作区、覆盖本地文件或执行其中内容，都需由本机用户明确决定
- 代码片段与文件外发前会在确认弹窗中展示（文件名、大小、源路径），请留意敏感内容
